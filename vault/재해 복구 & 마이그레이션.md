# 재해 복구 & 마이그레이션

> RPO/RTO와 4가지 DR 전략(백업·복원, Pilot Light, Warm Standby, 멀티 사이트).

## 개요

재해 복구(DR)는 "장애가 났을 때 데이터를 얼마나 잃어도 되고(RPO), 얼마나 빨리 복구해야 하나(RTO)"를 정하고, 그 목표에 맞는 전략을 고르는 일이다.

- **RPO (Recovery Point Objective)** — 마지막 백업 시점과 장애 시점 사이의 데이터 손실 허용량. 짧을수록 백업을 자주 해야 한다.
- **RTO (Recovery Time Objective)** — 장애에서 서비스 복구까지 걸려도 되는 시간.
- **4가지 DR 전략** — 비용·RTO가 낮은 순서대로: **Backup & Restore**(가장 쌈·느림) → **Pilot Light**(핵심만 띄워 둠) → **Warm Standby**(축소판을 늘 돌림) → **Multi-Site / Hot Site**(풀 사이즈 양쪽 운영, 가장 비쌈·빠름).

여기에 데이터를 옮기고 백업하는 도구가 붙는다. **DataSync**는 대량 파일을 온프레미스·AWS 사이로 옮기고, **AWS Backup**은 여러 서비스의 백업을 한곳에서 자동화하며, **Backup Vault Lock**은 그 백업을 지우지 못하게 잠근다. (DR 전략 자체의 상세는 설계 관점, 운영 도구는 운영 관점에서 다룬다.)

## 운영 관점 (CloudOps) #cloudops

![[AWS Certified CloudOps Engineer Associate Slides v41.pdf#page=469]]

CloudOps의 DR 단원은 전략 이론(RPO/RTO·4전략)보다 **실제 운영 도구 — 데이터를 옮기는 DataSync, 백업을 자동화하는 AWS Backup, 백업을 보호하는 Backup Vault Lock —** 에 집중한다. 신뢰성 도메인 22%.

### AWS DataSync — 대량 데이터 이동

- **에이전트 필요 여부가 출제 포인트.** 온프레미스·타 클라우드 ↔ AWS로 옮길 때는 소스 쪽에 **DataSync 에이전트**가 필요하다(NFS·SMB·HDFS·S3 API). 반대로 **AWS 스토리지 서비스끼리** 옮길 때는 **에이전트가 필요 없다.**
- 대상: **S3**(Glacier 포함 모든 스토리지 클래스), **EFS**, **FSx**(Windows·Lustre·NetApp·OpenZFS).
- **파일 권한과 메타데이터를 보존**한다(NFS POSIX·SMB). 이게 단순 복사 도구와 구분되는 핵심.
- 복제 작업은 **시간·일·주 단위 스케줄**(실시간 동기화가 아니다). 에이전트 태스크 하나가 최대 10 Gbps, 대역폭 제한 설정 가능.
- 회선이 느리면 **Snowcone**(에이전트 사전 설치)으로 오프라인 전송 후 DataSync로 잇는다.

### AWS Backup — 중앙 백업 자동화

- 여러 서비스의 백업을 **한곳에서 자동화**하는 완전 관리형 서비스. 직접 스크립트를 짜거나 수동으로 스냅샷 돌릴 필요가 없다.
- 지원: EC2/EBS, S3, RDS(전 엔진)/Aurora/DynamoDB, DocumentDB/Neptune, EFS/FSx(Lustre·Windows), Storage Gateway(Volume Gateway).
- **Cross-Region·Cross-Account 백업**을 지원한다 — DR과 직결되는 포인트.
- PITR(특정 시점 복구) 지원, On-Demand·스케줄 백업, **태그 기반** 백업 정책.
- **Backup Plan**으로 정책을 정의: 백업 빈도(12시간·일·주·월·cron), 백업 윈도우, **Cold Storage 전환** 시점, 보관 기간(Retention). 백업은 자동으로 S3에 저장된다.

### AWS Backup Vault Lock — 백업 보호

- Backup Vault에 저장된 백업에 **WORM(Write Once Read Many)**을 강제한다. 한 번 쓰면 못 지우고 보관 기간도 줄이지 못한다.
- 실수·악의적 삭제, 보관 기간 단축으로부터 백업을 지키는 추가 방어선.
- **활성화하면 root 사용자조차 백업을 지울 수 없다.** (S3 Object Lock의 백업 버전이라고 보면 된다.) "백업을 누구도 못 지우게 규정 준수" 시나리오의 답.

## 시험 함정

- DataSync는 **온프레미스↔AWS는 에이전트 필요**, **AWS 스토리지 서비스 간은 에이전트 불필요**. #exam/trap/reliability
- DataSync는 **파일 권한·메타데이터를 보존**(NFS POSIX·SMB) — 단순 복사와 구분. #exam/trap/reliability
- DataSync는 **스케줄 기반(시간·일·주)**, 실시간 동기화가 아니다. #exam/trap/reliability
- AWS Backup은 **Cross-Region·Cross-Account 백업** 지원 — DR 시나리오 단골. #exam/trap/reliability
- **Backup Vault Lock = WORM**, 활성화하면 **root도 백업 삭제 불가**. "누구도 못 지우게" → 이것. #exam/trap/reliability
- 4가지 DR 전략 비용·RTO 순서: Backup & Restore < Pilot Light < Warm Standby < Multi-Site. #exam/trap/disaster-recovery
